# 4. AI採点ロジック（PDAルーブリック厳密準拠）

本章は「評価基準_ルーブリック（PD検定対応）.xlsx」を唯一の根拠とする採点仕様です。
**AIは詳細項目の充足判定（true/false）と根拠引用のみを行い、点数計算はコード（RubricEngine）が行います。**
AIが点数を直接出力することはシステム上できません。

## 4.2 点数計算アルゴリズム（RubricEngine・決定的コード）

Excel「補足」列の規則をそのまま実装します。内容・表現それぞれについて：

```
入力: 4項目 × {B充足, A充足, S詳細項目ごとの充足} + 低得点ゲート判定

1. ゲート判定（C帯）
   該当すれば 0 / 1 / 2 点で確定（内容と表現で別々に判定）

2. B帯（3〜5点）
   B充足項目数 = 1〜2 → 3点
   B充足項目数 = 3   → 4点
   B充足項目数 = 4   → 5点

3. A帯（6点）
   4項目すべてのA基準を満たす → 6点

4. S帯（7〜10点）※6点を満たした場合のみ
   「特に評価できる項目」= その項目のS詳細項目のうち半分以上を満たす項目
   特に評価できる項目数 1 → 7点 / 2 → 8点 / 3 → 9点 / 4 → 10点
```

- 項目別の表示グレード：S詳細の半分以上充足かつA充足 → **S**、A充足 → **A**、B充足 → **B**、いずれも満たさない → **C**。
- カテゴリの細目表記（レポートの Matter / Manner 欄）：0–2点=**C**、3–5点=**B**、6点=**A**、7–10点=**S**（Excel D列と一致）。
- Total Score = Matter(0–10) + Manner(0–10) = 0–20。

### POI 関連項目の扱い（1人受験のため POI が発生しない）【要PDA承認 / Q2】

- 表現「態度」A基準の POI 条件：ルーブリック自身の除外規定「相手側からのPOIが1回以下の場合を除く」を適用。
  1人受験では相手POIが0回のため**この条件は常に免除**され、他の条件のみで判定します。
- POI を前提とする S 詳細項目（内容 role_strategy の1件、表現 attitude の1件）：
  **「特に評価できる」判定の分母から除外**します（例: role_strategy は3件中2件→2件中1件で「特に評価できる」）。
  受験者に不利にならない扱いであり、レポートに「Web受験版のためPOIは評価対象外」と注記します。

### Reply スピーチ（LOR / PMR、第2フェーズ）

- 詳細項目の［ ］内文言と時間閾値（B:1:00以上 / A:1:30以上 / S:2:30以内）を `speech_type=reply` で切替。
  ルーブリック定義に組み込み済みのため、役割追加時にコード変更は不要です。

## 4.3 判定材料の作り方（何をLLMに、何を計測に任せるか）

| 判定対象 | 方法 |
|-----------|------|
| Time Management（全帯域） | **決定的計測**：録画の発話開始〜終了時間。LLM不使用 |
| 沈黙が半分以下 / ほとんどない | **決定的計測**：STT単語タイムスタンプから沈黙率を算出（閾値: B=沈黙率≤50%、A=沈黙率≤10%目安※） |
| 声の大きさ・聞き取りやすさ | 計測（音量統計・STT信頼度）＋LLM補助 |
| 緩急・感情・淀みなさ（明瞭性S） | 計測（話速変動・ピッチ統計・フィラー/言い直し率）＋LLM補助 |
| アイコンタクト | **Vision判定**：0.5fpsのフレームを視覚モデルで「カメラ目線/下向き/横向き」分類→目線率。B/A/Sは「半分程度」「大部分」の文言に対応する閾値（B≥20%かつ意識的な顔上げあり、A≥50%、S≥80%目安※）＋重要箇所（挨拶・サインポスト時刻）での目線の有無 |
| ジェスチャー | Vision判定（フレーム内の手の動き・内容との対応はLLMがフレーム所見+文字起こしで判定） |
| 姿勢・敬意・自信（態度） | Vision所見＋音声所見＋LLM総合判定 |
| Matter 全詳細項目 | **LLM判定**：文字起こし＋論題＋RoleSpec（＋LOは生成PMスピーチ全文）を入力し、詳細項目ごとに true/false + 根拠引用 |

※「半分程度」「ほとんど」等の文言を数値化した運用閾値は設定マスタに置き、管理者が調整可能。
既定値は上記とし、PDA の運用フィードバックで較正します（ルーブリック文言自体は変更しない）。

## 4.4 LLM 判定の設計（2段階）

### 段階1: スピーチ構造抽出（Speech Sheet マッピング）

文字起こしを PDA スピーチシートの構成に対応付けます。

- PM: 挨拶 / 定義（必要な場合） / Government Point 1（サインポスト・理由・例） / Government Point 2 / Point 1 の詳しい説明 / まとめ
- LO: 挨拶 / **Government Point 1 への反論** / Opposition Point 1 / Opposition Point 2 / **Opposition Point 1 の詳しい説明** / まとめ
  （LO には AI 生成PMスピーチの全文を渡し、反論の対応関係＝どの主張への反論かを判定）

出力：各要素の有無・該当発話の引用・タイムスタンプ。これは Speaker Role（役割・戦略性）判定の一次材料であり、
管理者画面にもそのまま表示します。

### 段階2: 詳細項目の充足判定

ルーブリック定義の**詳細項目1件ずつ**について、以下を JSON Schema 強制出力で返させます：

```jsonc
{
  "criterionId": "matter.reasoning.S1",
  "met": true,
  "confidence": 0.86,
  "rationale": "肯定側でなければ生じない差（〜）を理由として説明している。",
  "evidence": [{ "quote": "If we ban ..., only the government side can ...", "startSec": 74.2 }]
}
```

- プロンプトにはルーブリックの**原文**、スピーチシートの役割定義、補足資料（Supplementary information）の解釈基準を
  そのまま埋め込み、「この基準以外で判断してはならない」「不確かな場合は met=false」と指示します。
- confidence < 0.6 の判定は管理者画面で「要確認」バッジ表示（判定自体は保存値を使用）。
- 温度0・同一プロンプトバージョンで再現性を確保。プロンプトはルーブリック定義と同様にバージョン管理。

### コメント生成（別ジョブ）

判定結果（8項目のグレード・充足/不足の詳細項目・根拠引用）を入力として生成します：

- ① Good Points ② Improvement Points ③ Overall Comments
- 各150〜200字・日本語・高校生が理解できる語彙・**内容（Matter）と表現（Manner）の両方に必ず言及**
- 不足だった詳細項目のうち改善効果が大きいもの（次の帯域に上がるために必要な項目）を優先して助言
- 生成後に文字数・言及範囲を自動検査し、不合格なら再生成

## 4.5 LO 受験時の PM スピーチ生成

- 論題ごとに**毎回** Claude で生成（`generated_speeches` に全文・構造・モデル・プロンプトverを保存）。
- 生成要件：PDAルール準拠の約3分（480〜560語目安）／挨拶→定義（必要時）→サインポスト→
  **Government Point 1（理由・例つき）→ Government Point 2 → Point 1 の詳しい説明**→まとめ、の構成。
- 生成後の自己検査：構成要素の有無・語数・論題との整合を自動チェックし、不合格なら再生成。
- TTS で音声化（自然な速度 約160wpm）。音声は cleanup 対象、スクリプトは永続保存（LO反論判定の前提のため）。
- 難易度は「高校生のLOが反論可能な、明確で標準的な立論」に固定（奇抜な論の生成を抑止するスタイル指示）。

## 4.6 PD Level 換算【暫定・要PDA承認 / Q1】

Total Score (0–20) → PD Level。**管理者画面で編集可能なマスタ**とし、暫定値：

| Total | PD Level（暫定） |
|-------|------------------|
| 18–20 | Level 6 |
| 15–17 | Level 5 |
| 12–14 | Level 4 |
| 9–11 | Level 3 |
| 6–8 | Level 2 |
| 0–5 | Level 1 |

正式な PD検定の級・レベル換算表のご提供をお願いします（提供後にマスタへ反映、コード変更不要）。

## 4.7 採点品質の担保

- **ゴールデンテストセット**：PDA 提供（または監修）のサンプルスピーチ＋人間ジャッジの正解判定を用意し、
  プロンプト・モデル変更時に一致率（項目グレード一致・±1点以内率）を回帰テストとして自動計測。
- 全採点結果に「AIによるアセスメントであり、公式PD検定の結果ではない」旨を明記。
- 管理者修正のデータは将来のプロンプト改善の教師データとして蓄積（evaluation_revisions）。
