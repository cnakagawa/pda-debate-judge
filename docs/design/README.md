## 設計原則

0. **学習支援システムである** — 本システムは採点が目的ではなく、受験者の成長が目的である。
   すべての評価は「なぜその評価か（根拠）」「スピーチシートのどこを改善するか」
   「次のPDレベルに上がるために何を練習するか」まで受験者に提示し、
   受験履歴からレベル・スコアの成長推移を可視化する（09-learning-support.md）。
1. **ルーブリック厳守** — AI は「詳細項目を満たすか否か」の事実判定のみを行い、
   点数計算はルーブリックの帯域規則を実装した**決定的なコード**が行う。AI独自の採点は構造的に不可能にする。
2. **判定根拠の全件保存** — 全評価項目について、判定理由と発話引用（エビデンス）をDBに保存し、管理者が確認・修正できる。
3. **修正可能性** — 管理者による評価修正は履歴（監査ログ）付きで上書きでき、レポート再発行に反映される。
4. **拡張前提の抽象化** — 音声認識・音声合成・LLM・録画ソース（Web/Zoom/Teams/Meet）・役割（PM〜PMR）・言語（英/日）を
   すべて差し替え可能なポート/アダプタ構造にする。
5. **5年以上の運用品質** — TypeScript による型安全、ルーブリックのバージョン管理、マイグレーション管理、自動テスト、監査ログ。

## 承認前に PDA 側の確認をお願いしたい事項（オープン課題）

| # | 課題 | 状態 / 提案 |
|---|------|--------------------------|
| Q1 | **PD Level の換算表** | ✅ **解決済み**：PDA提供の 内容×表現 マトリクス（PD1〜PD6）を採用。CEFR対応表も参考表示可能（04-scoring 4.6 参照） |
| Q2 | **POI 関連の評価項目の扱い**（1人受験のため POI が発生しない） | ✅ **承認済み**：表現「態度」のA条件はルーブリック自身の除外規定を適用。POI前提のS詳細項目は分母から除外（04-scoring 参照） |
| Q3 | ジェスチャー評価の限界（Webカメラは概ね上半身のみ） | 撮影範囲内で判定し、レポートに「Web受験版での判定」と注記 |
| Q4 | 受験者アカウント方式 | メールアドレス＋パスワードの簡易アカウント（履歴・レポート再取得のため）。認定・本人確認は行わない |
| Q5 | MVP の対象言語 | 英語ディベートのみ（日本語は第2フェーズ）。UI は日本語 |
| Q6 | 初期の論題プール | 管理者画面から登録可能。初期データとして PDA 提供の論題リストを希望 |

## 既存コードの扱い

本リポジトリには Zoom transcript 用の POI 自動ジャッジ試作（`server.js`, `src/`, `public/`）が存在します。
